## 新增 claude/ 模块（Go 版 Claude Code → ACP 适配器）

- 背景：Claude Code 不原生支持 ACP（对标官方 `@agentclientprotocol/claude-agent-acp` / Zed `@zed-industries/claude-code-acp`，均基于 Agent SDK）。新增第六个独立 Go 模块 `claude/`，CLI `claude-acp-bridge`，零第三方依赖，go 1.22，版本 `00.00.01`（唯一来源 `internal/protocol/frame.go` 的 `VersionString`）。
- 架构：与 codex 的「单进程多 thread」不同，Claude stream-json 是**每个 ACP session 一个常驻 `claude -p` 进程**。`internal/protocol`（ACP JSON-RPC 2.0 + 纯 NDJSON stream-json，后者无 jsonrpc 信封）、`internal/claudecode`（子进程、BuildArgs、Conn 请求关联/事件泵/控制协议、iface 接口）、`internal/bridge`（ACP server、session/turn、事件翻译、权限、UUID）。
- 协议事实来源：本机 `claude 2.1.322` 的 `--help` + 社区实测（spatie/bloom PROTOCOL.md、SDK 控制消息类型）。关键事实：`-p --input-format/--output-format stream-json --verbose --permission-prompt-tool stdio --permission-mode`；`system/init` 首条用户消息后才发 → 桥自生成 UUID 经 `--session-id` 前置；`can_use_tool` 控制请求走 ACP `session/request_permission`；`result.subtype` 区分 end_turn/max_tokens/error；`interrupt`/`set_model`/`set_permission_mode` 控制请求；未知事件/子类型安全忽略。详见 `claude/docs/protocol.md`。
- 关键设计：launch 必须用长生命周期 ctx（`exec.CommandContext` + `defer cancel()` 会杀子进程，e2e 曾踩坑）；cancel 直接 finish turn 不等 CLI result；`StreamFrame` 剔除 jsonrpc 成员；stream 增量按 index 累积与完整 assistant 块去重。
