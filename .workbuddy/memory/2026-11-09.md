# 2026-11-09

## 新增 codex/ 模块（Go 版 Codex → ACP 适配器）

- 背景：Codex CLI 无原生 ACP，需适配器模式（对标 `@agentclientprotocol/codex-acp`）。新增第五个独立 Go 模块 `codex/`，CLI `codex-acp-bridge`，零第三方依赖，go 1.22，版本 `00.00.01`（唯一来源 `internal/protocol/frame.go` 的 `VersionString`）。
- 架构：`internal/protocol`（ACP JSON-RPC 2.0 帧 + app-server JSON-RPC **lite** 帧，后者必须省略 `jsonrpc` 成员）、`internal/codexapp`（子进程、握手 initialize+initialized、请求关联、通知泵、反向请求）、`internal/bridge`（ACP server、session/thread 映射、turn 状态机、事件翻译、权限、历史重放）。
- 关键设计：常驻 reader + 按 id 路由回复，支持「Codex 审批请求 → ACP session/request_permission」嵌套 RPC 不死锁；turnState 在 `turn/start` 发出前注册（通知可能早于 RPC 响应）；失败不伪装 end_turn，推文本 + 返回 JSON-RPC error；stdout 只走 ACP 帧。
- 协议事实来源：本机 `codex-cli 0.167.0` 的 `codex app-server generate-json-schema` 导出（不是猜测）。决策枚举 v2 为 accept/acceptForSession/decline/cancel，旧版 approved/approved_for_session/denied/abort。详见 `codex/docs/protocol.md`。
- 子命令 `serve` / `doctor`（只读握手，不发 prompt、不调模型）/ `version`；配置见 `codex/README.md`。
- 验证：`go vet ./...`、`go test ./...`、`go test -race ./...` 全绿；`test/e2e` 用 Python 假 app-server 驱动编译后的真实二进制；真机 `doctor` 与 codex-cli 0.167.0 握手成功（userAgent/codexHome/platform*）。
